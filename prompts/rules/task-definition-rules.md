# Task Definition Rules

Ein Task besitzt ein fachliches Ziel, konkrete Pfade, Scope/Out-of-Scope, Verhalten, Spec-Referenzen, Abhängigkeiten, Akzeptanz, Tests, Befehle, Risiko, Skills und Routingrahmen.

Teilen bei mehreren Zielen/Layers, unklarer Verifikation, Architekturentscheidung oder typischerweise mehr als 3–5 Dateien. „Und“ im Titel ist Warnsignal. Zu klein ist ein Task ohne eigenständigen Nachweis.

Keine Implementation vor unabhängigem `task_review -> ready`. Jeder geänderten Funktion entspricht ein Test oder genehmigter manueller Nachweis.
