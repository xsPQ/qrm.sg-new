# Git Rules

Vorher `git status --short --branch`; nachher `git diff --stat`, `git diff`, Status. Projektworkflow aus `docs/context/git-rules.md` gilt.

Fokussierte Branches/Commits, `<type>: <description>`, absichtliches Staging. Keine fremden Änderungen, Secrets, Builds, Dumps oder lokalen Daten. Kein Reset Hard, Clean, Force Push oder History-Rewrite ohne Auftrag. Commit/Push/PR/Merge/Tag nur wenn autorisiert.

PR, falls genutzt: Task/Spec-Links, Scope, Tests, Risiken, Migration/Rollback und Reviewer.
