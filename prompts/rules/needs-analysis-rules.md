# Needs Analysis Rules

Nur aus `spec_ready` ableiten: Sprachen, Frameworks, Daten, Build/Test, Runtime, Deployment, Docker/CI, APIs, Rollen, Skills, Risiken, Security-Trigger, Ressourcen und Budget.

„erforderlich“, „bevorzugt“ und „optional“ trennen. Jede Entscheidung verweist auf Spec/Constraint; neue Architekturannahmen zurück an Spec/ADR. Tools, Adapter und Budget real prüfen.

Gate: Muss-Anforderungen abgedeckt, kritische Risiken kontrolliert, Test-/Betriebsweg real, keine blockierende Lücke.
